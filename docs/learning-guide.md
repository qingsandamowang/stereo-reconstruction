# 学习说明：双目视差与三维重建

## 核心概念

左右相机从略微不同位置拍摄同一场景。校正后的同一点基本位于同一图像行；左图横坐标减右图横坐标得到视差 `d`。物体越近，视差通常越大。ETH3D 提供相机焦距 `f`、主点 `(cx, cy)`、基线 `baseline` 和主点差 `doffs`。按其采用的 Middlebury 标定格式，深度计算为 `Z = baseline × f / (d + doffs)`；本项目导出单位为毫米。

读取 `io.py` 可了解 PFM 的浮点、大小端和自下而上存储方式。`geometry.py` 再用 `X = (x − cx)Z/f`、`Y = (y − cy)Z/f` 生成三维点；无效或过远点会被过滤。项目使用公开标定，不是自己完成相机标定实验。

## 匹配算法

StereoBM 用局部窗口比较候选位置。StereoSGBM 在局部匹配的基础上沿多方向累计代价，能覆盖更多弱纹理区域。参数包括视差搜索范围和匹配窗口大小，全部在 13 个验证场景上选择，14 个测试场景未参与选择。`matching.py` 还实现左右一致性：左图某点向右图寻找对应点后，再由右图回查，若两次视差不相符就丢弃。

## 如何读结果

EPE 是有效预测点的平均绝对视差误差；Bad 2px 是误差超过 2 像素的比例。本项目的 `bad2_all` 还把没有输出视差的有效真值点计作错误，防止靠大量拒绝难点来获得好看的 EPE。`coverage` 是有有效预测的真值点比例。ETH3D 掩码中 255 才表示双目都可见，128 仅左目可见，评估时必须排除。SGBM 的 18.5% Bad 2px 与 88.8% 覆盖率应一起阅读；一致性过滤将 EPE 从 1.768 降至 1.155 px，却将覆盖率降到 79.0%。

`results/eth3d_v2/visuals` 的对比图依次展示左图、真值视差、SGBM 视差和 0–5 px 误差图。三个 PLY 可以用 MeshLab 或 CloudCompare 查看。点云可用于展示深度几何，但在遮挡、反光和无纹理区域可能出现孔洞或离群点。

## 建议自己动手的顺序

1. 阅读一个场景的 `calib.txt`，手算给定视差的 Z、X、Y，再运行 `tests/test_geometry.py` 对照。
2. 画两条极线，解释为什么校正后的搜索主要沿水平方向，以及左右一致性为何会降低覆盖率。
3. 在 `validation_candidates.json` 中找出选择的 `num_disp` 和 `block_size`，说明窗口大小对边界和低纹理区的影响。
4. 比较 `forest_1s`、`playground_2l`、`terrains_1s` 的误差图，找出遮挡、反光或重复纹理导致的错误。
5. 独立运行一次 `python -m stereolab.benchmark`，核对 14 个场景的报告和三份点云。

面试时应说清楚公开数据来源、Codex Agent 的协助、自己理解的视差到深度公式、场景级划分和覆盖率/误差权衡。这个项目不等同于实现了双目结构光投影系统。
